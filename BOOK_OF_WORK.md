## Open questions (need a decision)

- **Small sectors look artificially strong** (sector breadth, 2026-11-17): a sector with 2 stocks both above the 20 MA shows 100% and tops the ranking (on 16 Nov 2026 "Diversified", 1 stock, ranked first). Options: shrink toward the market average (Bayesian / Wilson lower bound), or show a confidence marker. Current behaviour: stock counts shown, "Min stocks" filter (default 5) hides small sectors, ties broken by size.
- **Backtest survivorship bias** (backtest, 2026-11-17): index membership history only exists from when watchlist syncing started, and delisted stocks are missing from Angel's scrip master, so older backtests use today's survivors. Options: source historical index constituents (NSE archives), flag affected date ranges in reports. Not started; backtest plan awaiting go-ahead.

## Known limitations

- **Frontend has no automated tests** (frontend, 2026-11-18): there is no test runner (scripts are only dev/build/typecheck/preview), so UI logic is checked only by typecheck and by hand in the browser. First candidates: the chart side list (`features/charts/chartList.ts`: keeps the last 10 lists, unknown/empty id gives no list, corrupt stored JSON doesn't crash, single-stock lists add no pane; `toListItems` with null change) and `DataTable` passing rows in sorted order with missing values last. Also the chart range tools (`components/charts/ranges.ts`, 2026-11-18): `barIndex` before the first bar / on gaps, `rangeLabel` for a zero-length range, a zero or negative start price (no %), whole-day vs intraday durations. Also the Watchlists tab (`features/watchlists/WatchlistPane.tsx`, 2026-11-18): the stale-bar date note (`toChartList`: no bars, one stock behind the rest), falling back to your first list on an unknown `wl`, and charting the first stock after switching lists; checked by hand only. Option considered: Vitest (fits the Vite setup; one dev dependency, a `test` script, small config). Deferred by choice.
- **Chart side list isn't in shared links** (chart UI, 2026-11-18): the list beside the chart (scan results, sector stocks, Overview cards) is stored in the browser tab's sessionStorage, and the URL only carries its id, so a copied link, another tab or another device opens the chart without the list. It's a snapshot of the list's date and order at the time of the click. Option: put the source in the URL (scan definition, sector + universe + sort) and re-run it on the chart page; needs a resolver per list type and long URLs for big scans. Accepted as is for now.
- **Traded-stocks list includes ETFs and splits on series changes** (data, 2026-11-18): `nse_traded` is every NSE `-EQ`/`-BE`/`-BZ` instrument whose Angel quote shows a trade in the latest session. Angel lists ETFs like stocks, so ~200 ETFs are in it (kept by choice; dropping by name pattern was the alternative). A stock moving between EQ and BE gets a new Angel symbol and token, so its history splits across two instruments; fix by linking on ISIN (not in Angel's scrip master, so it needs another source). On this universe the Overview movers fill with illiquid circuit-hitters; a minimum-turnover filter would fix that.

- **No sector for stocks outside Nifty Total Market** (data, 2026-11-18): NSE's index files (niftyindices.com) carry an Industry column, and the broadest, Nifty Total Market, covers ~750 stocks. NSE's full equity list (`EQUITY_L.csv`, ~2,600 stocks) has no sector. Options: NSE's per-stock quote API (`industryInfo`: macro, sector, industry, basic industry), which is unofficial, cookie-gated and rate-limited; BSE's scrip list (industry per scrip, matched by ISIN), which is also unofficial and uses BSE's own classification; or a paid data vendor. Current behaviour: those stocks show as "Unclassified" in sector views.

- **Public link serves the Vite dev server** (launcher, 2026-11-17): the ngrok tunnel points at `npm run dev`, so remote loads are unbundled and slower, and the only protection is ngrok basic auth (one shared password; the app itself has no login). Options: serve the built `frontend/dist` from FastAPI on one port; ngrok Google login instead of a password. Current behaviour: works, protected by `ngrok-policy.yml`.

- **Sector breadth has no version guard (next up)** (sector breadth, 2026-11-18; narrowed 2026-11-19): a change to its SQL or to the industry mapping still needs `markets breadth --backfill` by hand. (Old bars changing is now handled: the nightly update recomputes from the earliest bar re-downloaded since the last run, or removed by the repair step.) The user wants this tackled soon. Option: a version constant for the breadth SQL and mapping that triggers a backfill when it changes, like `DQ_VERSION` / `ATH_VERSION`. Current behaviour: manual backfill following `derived-data.md`.
- **Other stored derived data isn't rebuilt automatically** (data, 2026-11-18): found while writing `.claude/skills/markets-codebase/references/derived-data.md`. (2) Days before a watchlist's first sync use its current members, so every index rebalance silently changes older stored breadth until the next backfill. (3) `calc_values` rows are upserted, never deleted: a value that becomes NaN after a bar fix, or a bar deleted by hand, keeps its old stored value (bars removed by the repair step do have their values deleted). (4) An indicator's `code_hash` covers only its own function, not helpers it calls. Options: for (2), the breadth version guard above would cover it if membership changes count as a trigger; for (3), replace an instrument's calc series instead of upserting; for (4), bump versions by hand. Current behaviour: rebuilds are manual, following the registry.
- **Stored breadth can lag ad-hoc fetches until the night** (sector breadth, 2026-11-17): a day's breadth is stored on first read; bars fetched later that day via the Data page or "Fetch latest" show up in stored breadth only after the nightly update (which now recomputes from the earliest re-downloaded bar, whatever its age). Fix if it matters: recompute breadth after any ingest.
- **Sector labels are not point-in-time** (data, 2026-11-17): `instrument_tags.industry` holds only the latest NSE classification, so past sector breadth uses today's labels. Fix: keep tag history like `watchlist_members` does.
- **No way to set your own sector mapping** (data, 2026-11-18): the industry tag is joined at query time, but every NSE watchlist sync upserts `instrument_tags.industry` and would overwrite a hand-edited value. Stored `sector_breadth` is aggregated by sector name, so a mapping change only reaches history after `markets breadth --backfill` (the nightly job recomputes only the last 10 days, leaving old and new labels mixed). The join is also written twice (`DuckMarketRepository.snapshot`, `DuckBreadthRepository._sql`). Options: an override tag (source `manual`) that sync never touches; or (preferred by the user, 2026-11-18) the user supplies the whole stock-to-sector map and the NSE sync stops writing industry tags (it keeps syncing index membership), with unmapped stocks shown as "Unclassified" and flagged by the nightly audit. Either way: one shared sector view for the joins, and the command that loads the mapping rebuilds stored breadth (`markets breadth --backfill`) itself. Current behaviour: NSE's classification only; parked for now.
- **Data-quality checks: limits of the first version** (data, 2026-11-18): (1) incremental runs only see bars (re)ingested since the last run, so a bar deleted or edited in place without a new `ingested_at` is only caught by `markets dq check --full`; (2) zero-volume bars on illiquid stocks may be numerous; if the first full run is noisy, options are accepting them per stock, dropping zero volume from `bad_bar`, or flagging only stocks with many; (3) the 35% jump threshold will also flag genuine moves on stocks without circuit limits (rare); (4) the audit is a Claude desktop scheduled task (19:00 Mon–Fri, after the 17:00 update; saved in Auto mode): it runs only while the app is open, otherwise at next launch; (5) the first full check runs with the first nightly update after the backend is restarted.
- **One process can open the database** (infra, 2026-11-17): DuckDB locks the file, so research scripts can't read it while `markets serve` runs. Planned fix: nightly `EXPORT DATABASE` snapshot that research loads into memory.
- **Long scan URLs** (scans UI, 2026-11-17): the filter tree is stored as URL-encoded JSON. Works, but links are long and unreadable. Option: compact or base64url encoding.

## Bugs

- **Day-long holes in Angel's history for liquid stocks** (data, 2026-11-18, first full DQ run): whole sessions missing for stocks that certainly traded. 2024-03-28: 392 stocks incl. SUZLON, JIOFIN, SCHNEIDER, RRKABEL, WOCKPHARMA, AARTIPHARM (bars on 27 Mar and 1 Apr, none on 28 Mar). 2023-01-09 → 01-31 (16 sessions): RECLTD, PATANJALI, EMBASSY-RR, BIRET-RR. 2023-01-13: ETERNAL, SBILIFE, ATGL, GVT&D, GODFRYPHLP. Multi-year holes: GOODYEAR, KENNAMET, KIRLFER, KOVAI, GRAUWEIL, EVONILE (2023-10-26 → 2026-04-17, 614 sessions; these 6 also show a "jump" on 2026-04-20 that is just the hole), WATERBASE, ANDREWYU, LANCER, VISHAL (→ 2026-08-14); FORCEMOT 2023-10-26 → 2024-02-13. All bars were downloaded 17–18 Nov 2026, so this is what Angel returned then (not a chunk-boundary bug: the 28 Mar hole doesn't line up with 2000-day chunk edges). Nifty 500 has 33 stocks with gaps (59 issues). Options: (1, recommended first) re-download one window per cluster to see if Angel now returns it, e.g. `markets ingest NSE:SUZLON-EQ --start 2024-03-27 --end 2024-04-01` and `markets ingest NSE:GOODYEAR-EQ --start 2023-10-20 --end 2026-04-20`; if it fills, re-download all affected stocks for those windows; (2) fill holes from NSE's bhavcopy (see the Ideas item; one file per missing day); (3) accept as provider holes. Current behaviour (2026-11-19): the nightly repair step re-downloads gap issues of Nifty 500 / Total Market / benchmark stocks (up to 50 a night, once a week each) and accepts them as "provider hole" after 3 tries; derived data follows by itself. Still open: holes on other stocks, and whether to fill provider holes from the bhavcopy.
- **SALASAR history mixes adjusted and unadjusted bars** (data, 2026-11-18): from 2022-09-08 to 2023-08-31 stored bars flip between ~6 and ~33 (e.g. 7 Sep 6.74, 8 Sep 33.95, 9 Sep 6.80), giving 88 `jump` issues. Angel's data, not ours. Charts, indicators and breadth for SALASAR are wrong over that year. Options: re-download to see if Angel has fixed it (`markets ingest NSE:SALASAR-EQ --start 2022-09-01 --end 2023-09-30`); if not, delete the outlier bars (on a factor-of-~5 basis) or rescale them; or accept. Bar changes → `markets breadth --backfill`.
- **Stored history isn't split/bonus adjusted for many stocks** (data, 2026-11-18): about 130 `jump` issues are drops of 60–99% with no gap before them, e.g. INDIAGLYCO 2026-09-02 (1,112 → 225), KSOLVES 2021-06-04, ALLCARGO 2025-11-12, and ETF unit splits at exactly −90% (BSLNIFTY, ABSLBANETF 2021-11-25; NIFTYBETA 2023-09-25; HDFCSENSEX 2024-02-02). Since all history was downloaded this week, Angel itself returned these unadjusted, which contradicts the premise of the "Re-fetch history after splits/bonuses" idea (that re-fetching gives adjusted history). Moving averages, breadth and scans across these dates are distorted. Options: adjust ourselves from a corporate-actions source (NSE corporate actions file; most reliable); detect splits as a jump whose ratio is close to a simple fraction (1/2, 1/5, 1/10) with no gap and adjust prior bars (cheap, will mis-fire on some crashes); or accept and only flag. Needs a decision before the split re-fetch idea is built. Genuine moves among the jumps (accept): YESBANK Mar 2020, IDEA 2019–20, CANBK/PNB 2017-10-25, INDUSINDBK/BANDHANBNK 2020-03-26, ZEEL 2021-09-14, POLICYBZR 2026-09-24 (27M shares traded).
- **Zero-volume bars: one systematic stock, the rest illiquid** (DQ, 2026-11-18): 2,204 of 2,213 `bad_bar` issues are "no volume". INSECTICID alone has 1,454: every bar from 2016-11-21 to late 2022 has volume 0 with normal prices (Angel has no volume for that period). The other ~750 are across ~160 illiquid EQ/BE/BZ stocks and ETFs, clustered Jun–Aug 2023. Only 9 bars have a missing/zero price. Options: accept INSECTICID's range (needs a bulk accept; `markets dq accept` takes one id at a time); drop zero volume from `bad_bar` for non-index stocks, or flag only stocks with many; keep zero/missing price as real errors. Ties into limitation (2) of "Data-quality checks: limits of the first version".
- **Gap check is dominated by illiquid stocks** (DQ, 2026-11-18): 15,712 open `gap` issues across 898 instruments, but 15,597 are in `nse_traded` and only 59 in Nifty 500. Most are 1–4-session gaps on BE/BZ stocks and ETFs that simply didn't trade (half the gaps are a single session; 82 stocks have suspensions of 60+ sessions, e.g. SICAGEN, ARIHANT, ATLASCYCLE). Also missing Muhurat-session bars for illiquid stocks (2024-11-01, 2025-10-21, 2026-11-08), which count as sessions. As is, real holes (entry above) are buried. Options: run `gap` only on index members (nifty500 / niftytotalmarket / benchmarks) or only on stocks that trade on most sessions; ignore gaps that end in a big jump on BE/BZ stocks (suspension and relisting); exclude Muhurat sessions. Index holes to accept: Nifty 50 2017-08-28 → 09-12 (known Angel hole), Nifty Fin Service 2017-10-18 → 11-02 and 2021-11-18 → 12-13, India VIX 2021-02-12 and 2021-03-30.
- **Nightly candle downloads run at about half the planned speed** (data, 2026-11-18): the limiter allows the documented 2/s and 78/min for `getCandleData`, but Angel rejects with "exceeding access rate" after roughly 45 requests (about 22 s at 2/s). Each rejection then costs 45 s of backoff (15 s, then 30 s), because the 15 s retry also fails. Effective rate is about 35–45 stocks a minute, so the ~3,040-stock run takes about 80–90 minutes instead of ~40. On 18 Nov the run started at 18:00 (not 17:00) and finished at 19:31, after the 19:00 audit's scheduled time. Options: measure what Angel really allows and set the per-minute limit to it, pacing requests evenly (no bursts, no penalties); and/or after a rejection, wait for the minute window to clear once instead of retrying at 15 s. Also check why the scheduled run started at 18:00. Current behaviour: correct but slow.


## Ideas (later)

- **Live market data** (dashboard, 2026-11-18): show prices during market hours instead of only the nightly daily bars. Options: Angel One's WebSocket stream (`angelone-smartapi` skill has the reference; token-subscription limits apply) pushed to the frontend, or polling the Quote API on a timer (shares the rate budget with ingestion). To decide: which pages go live (chart, Overview, the Watchlists tab: the natural first candidate, since lists are small and well under the WebSocket token limits; its rows already come from one query, `useWatchlistQuotes`, so live prices could replace the stored last close there), whether today's forming bar is written to DuckDB or kept in memory until the nightly job stores the official bar, and what to show outside market hours.
- **IPOs page** (new page, 2026-11-18): watch stocks that listed since 1 Jan 2024 (thesis to experiment with: rally after listing, fall, base, breakout; no rules yet). Agreed shape: an `ipos` DuckDB table (symbol, listing date, issue price where known) joined to stored daily bars; a new `/ipos` tab with a sortable table (listed, days since listing, listing price = first bar's open, close, vs listing, high since listing, % off that high, low since that high, volume vs 20-day average) and a Table | Charts switch reusing `features/charts/ChartGrid`; rows open the chart via `useOpenChart`; also offered as a universe on Overview/Scans. Exclude demergers; keep SME→main-board migrants; NSE Emerge SME stocks left out for now. Blocker is filling the table: NSE's `EQUITY_L.csv` "date of listing" gives 732 stocks since 2024 but includes ~245 old BSE companies admitted in two bulk batches (20 Apr 2026: 103, 17 Aug 2026: 142; normal days list at most 6), ~100 more single BSE→NSE moves (e.g. FORCEMOT, SAURASHCEM), demergers (ITCHOTELS, ENRIN, ABLBL, TMCV, Vedanta's four on 15 Jun 2026) and SME migrants; ISIN doesn't separate them. Options: (1, recommended) user downloads NSE's past-issues CSV from the IPO page and a `markets ipos import <file>` command loads it, re-run every few weeks, also accepting a hand-written symbol/date CSV; (2) seed from `EQUITY_L.csv` minus dates with ≥20 listings (~487 left) and prune by hand; (3) fetch NSE's `/api/public-past-issues` nightly (unofficial, cookie-gated, untested; a browser fetch was blocked here). Parked by choice; nothing built.

- **Daily bars from NSE's bhavcopy** (data, 2026-11-18): NSE publishes one end-of-day file per session (`BhavCopy_NSE_CM_0_0_0_<yyyymmdd>_F_0000.csv.zip` on nsearchives.nseindia.com) with open/high/low/close/volume for every traded security. One download could replace ~2,600 Angel requests a night (seconds instead of ~35 min). Caveat: the bhavcopy is not adjusted for splits and bonuses, while Angel's history is, so the two would need reconciling.

- **F&O stocks universe** (scans/overview, 2026-11-18): flag F&O stocks and offer "F&O stocks" in the universe dropdown on Overview and Scans. Sketch: an `fno` watchlist synced nightly from the stored scrip master (underlyings of live NFO `FUTSTK` contracts, mapped to NSE `-EQ`), so membership history and nightly price fetching come for free. Caveats: no history before the first sync (NSE publishes past changes), excluded stocks linger until their last contract expires (up to ~3 months), name mismatches skipped and logged.
- **Open-interest signals for F&O stocks** (scans, 2026-11-18): use futures OI (long/short build-up, OI change vs price change, PCR) as scan signals on the F&O universe. Angel's OI build-up and PCR APIs cover today only, so history has to be collected nightly from now on (or daily futures candles, which carry OI); nothing can be backfilled from Angel. Depends on the F&O universe being in place.
- **Sector breadth over time** (overview, 2026-11-17): time-series charts of sector breadth (e.g. each sector's daily rank or % above its MA as a line, to see a sector inching up rather than one jump). The rank-change table is built (Rotation view on the Overview's Sector breadth card). - **Claude review of scan results** (scans, 2026-11-18): scanner handles the measurable rules; Claude reviews each candidate's chart image plus last 30–60 bars as numbers against a written rubric and labelled example charts, returning yes/no/maybe, a 1–5 score and a reason, shown as columns on the results ("Review with Claude", optionally overnight on saved scans). - **1-minute intraday history** (data, 2026-11-18): set aside as too large for now. Angel gives 30 days of 1m per request at ~78 requests/min (shared with the daily job): Nifty 500 × 5 years ≈ 31k requests (~7 h) and ~20 GB at today's ~90 bytes/row; all traded stocks ≈ 185k requests (~40 h) and 100+ GB. If revisited: start with Nifty 50/500 and 1–2 years, store only 1m and build 5m/15m/1h in SQL aligned to 9:15, keep daily bars from the daily feed (official close is a 30-min weighted average and daily is split-adjusted), move the DB out of OneDrive first, and test how far back Angel's 1m data goes.
- **Re-fetch history after splits/bonuses** (data, 2026-11-18): Angel's daily history is split/bonus adjusted, so after a corporate action our stored older bars no longer match and show a fake gap. Plan: in the nightly job, re-fetch the last few stored daily bars per stock and compare closes; if they differ (beyond rounding), re-download that stock's full daily history and overwrite it, then drop its cached calc values. Comparing overlap beats detecting a big one-day move (real crashes and circuits would trip that). Breadth rows already stored for past days would also be stale (the all-time-high cache, `daily_ath`, refreshes itself from re-downloaded bars). Until then, split stocks also look far below their 52-week/all-time high in the Sector breadth near-high column. Intraday bars: check whether Angel adjusts them before relying on them across a split.

Planned as lightweight-charts series primitives in `components/charts/drawings/`, a `chart_drawings` table plus repo and endpoints copying saved scans. Open questions then: per stock or per stock and interval (leaning per stock), whether drawings can be dragged, and extras (rays, rectangles, Fibonacci, snapping to OHLC). Set aside in favour of unsaved price/date range tools only.
