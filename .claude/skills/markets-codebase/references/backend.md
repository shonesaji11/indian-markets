# Backend map (`backend/src/markets/`)

Python >= 3.9, package `markets` (`backend/pyproject.toml`; extras `angelone`, `dev`; `xgboost` pinned for the big-movers model; model files in `src/markets/models/`). Line counts are approximate; Grep for the symbol, then read only that range.

## core/ (shared types and interfaces)

| File | Symbols |
|---|---|
| `core/models.py` | `CANDLE_COLUMNS`; `Interval` enum (`.duration`); dataclasses `Instrument`, `ProviderInstrument`, `DateRange` (`.chunks(max_span)` splits windows), `IngestionResult`, `LiveTick` (one streamed quote: exchange, token, ts, ltp, open/high/low, prev_close, volume) |
| `core/ports.py` | Protocols: `MarketDataProvider` (`list_instruments`, `fetch_candles`, `last_trade_dates`, `close`), `LiveFeed` (`max_subscriptions`, `connect(on_tick, on_close)`, `subscribe(refs)`, `close`; refs = (exchange, provider token)), `ConstituentSource`/`Constituent`, `InstrumentRepository`, `CandleRepository`, `IngestionLog`, `CalcRepository`, `Notifier` (`send(text)`; errors must not contain credentials) |

## Wiring and config

| File | Symbols |
|---|---|
| `config.py` | `Settings` (env `MARKETS_*`, `backend/.env`; `telegram_bot_token` + `telegram_chat_id` turn on alert messages and the evening big-movers message; `movers_cutoff` = probability a stock needs to be on the big-movers list, default 0.20), `get_settings()` (cached), `BACKEND_DIR` |
| `bootstrap.py` | `Container` dataclass (db, all repos, registry, provider, services incl. `screener`, `data_quality`, `ath`, `repair`, `live`, `alerts`, `movers`; `.close()` stops alerts and the live feed), `build_container(settings, provider, db, ..., live_feed, notifier)` (runs migrations; `always_streamed` = benchmarks + your lists + stocks with an active alert; `notifier` defaults to Telegram from `.env`) |
| `universes.py` | `WatchlistSpec`, `WATCHLISTS` (nifty500, nifty50, niftytotalmarket, nse_traded, benchmarks, sectors), `DEFAULT_UNIVERSE = "nifty500"`, `BREADTH_UNIVERSES`, `BREADTH_PERIODS` (10, 20, 50, 200: stored daily) |
| `cli.py` | `main()`; commands `init-db`, `sync-instruments`, `search`, `ingest`, `compute`, `coverage`, `update` (nightly), `dq report|check|accept` (falls back to the API when the server holds the DB), `breadth [--backfill]`, `highs [--rebuild]` (all-time-high cache), `movers [--since D] [--rebuild]` (score the big-movers list for the latest session, or every session since D; no message), `repair` (the nightly steps after downloading, now), `watchlists`, `serve`. `update`, `breadth`, `highs`, `movers` and `repair` go through the running API when the server holds the DB (`_post_api`). `update [--scheduled]` also appends a short per-run block to `backend/logs/nightly-summary.log` (`summary_block`, `_append_summary`) |

## engine/ (pure computation)

| File | Symbols |
|---|---|
| `engine/registry.py` | `IndicatorSpec` (`code_hash`, `resolve_params`, `calc_id`, `compute`, `describe`), `IndicatorRegistry` (`register/get/all`), `@indicator(name, version, outputs, description)`, `default_registry()` |
| `engine/indicators/trend.py` | `sma`, `ema`, `macd` |
| `engine/indicators/momentum.py` | `rsi` |
| `engine/indicators/volatility.py` | `atr`, `bollinger`, `adr_pct(period=20)` (ADR%: 100 × (mean high/low − 1)) |
| `engine/indicators/volume.py` | `volume_avg(period)`, `relative_volume(period)` (both average the bars *before* the current one) |
| `engine/screener.py` | Custom scans: filter tree (groups `match` all/any → conditions `left op right`; daily bars only (`TIMEFRAME`); operands = `FIELDS` of daily_signals_v1 (no avg/relative volume: use the volume indicators) or any registered indicator + params + output; ops gt/gte/lt/lte/crosses_above/crosses_below; percent fields take %; any operand may carry `ago: {n, unit d/w/m}` = N × 1/5/21 sessions back, max 252 (`AGO_UNITS`, `MAX_AGO_BARS`, `bars_ago`, `ago_sessions` validates one offset, also used by sector rotation)). `validate`, `iter_operands`, `operand_key` (`rsi(14)`, `sma(20)@1w`), `operand_label` (`RSI 14`, `SMA 20 · 1w ago`, `ADR% 20`), `uses_crossovers`, `evaluate` (vectorized masks), `indicator_frame` (wide ts × instrument; too little history = NaN, never a shorter window), `lookback_bars`. Missing values never match: no bar on the session asked for (offsets and the crossover's session before), or too little history, leaves the stock out |
| `engine/movers.py` | Big-movers features (ported from `research/movers/features.py`, night-before only): `build_features(stocks, nifty, vix, target=None)` → one row per stock and session t with `FEATURE_COLUMNS` known at the t-1 close (training: every session + target `move`/`big`; `target` = a date after the bars: only that session, for scoring); eligibility = traded on the Nifty's previous session + `MIN_BARS` (60); `FEATURES_VERSION` (bump on any logic change, then train a new model), `BIG_MOVE` (4%), `HISTORY_BARS` (500: 252-bar windows + ATR warm-up), `next_weekday` (assumed next session), `wilder_atr` |
| `engine/performance.py` | `basket_performance(bars, start)` → `BasketPerformance(stocks, path, counted)`: equal-weight buy-and-hold of stocks picked on the start session, bought at the next valid open (0 until bought); gaps carry the last close, stocks with no usable bar after the pick are listed but not counted; no stops/exits; end = last stored daily close (partial if daily bars were downloaded in market hours, e.g. from the Data page) |
| `engine/data_quality.py` | Pure DQ checks over long-format daily bars → issues (`instrument_id, start_ts, end_ts, detail`): `trading_sessions(counts)` (market calendar: days with ≥25% of a typical day's stocks), `find_gaps`, `find_bad_bars` (zero/NaN price, high<low, zero volume except indices), `find_jumps` (>35% close move, indices exempt), `find_stale` (>3 sessions behind), `find_short_history` (<200 bars). Constants + `DQ_VERSION` (bump on any logic change → next run is full) |
| `engine/scans.py` | Built-in overview scans: `Scan` (`.run(snapshot, limit)`), `@scan(...)`, `SCANS`; scans `top_gainers`, `top_losers`, `volume_shockers`, `new_52w_highs`, `new_52w_lows`, `gap_ups`, `gap_downs`; `breadth(df)` |

| `pipelines/daily_update.py` | `DailyUpdateService.run(sync_instruments, sync_watchlists)` → `DailyUpdateReport` (last step: `data_quality.run()`, summary in `report.data_quality`; `new_instruments`/`new_bars` count stocks backfilled because they had no daily bars, `failed_symbols` names failures) (nightly: sync, daily bars for tracked ids, then `_after_download`: `repair.run()` (`report.repair`), `ath.refresh()` (`report.ath_rows`), `breadth.update(since=earliest removed bar)`, data quality, then `movers.nightly()` (`report.movers`; its warnings go to `report.errors`)); `repair_now()` runs only `_after_download` (`markets repair`, `POST /jobs/repair`) |
| `pipelines/data_quality.py` | `DataQualityService.run(full, checks, instrument_ids)` (incremental by `candles.ingested_at` watermark in `dq_state`; bar checks from the bar before the first new one; full on first run / version change / `full`; scoped runs don't move the watermark; records + resolves issues), `report(status, check, instrument_id)`, `accept(issue_id, note)`; `CHECKS`, `BAR_CHECKS`, `GLOBAL_CHECKS` |
| `pipelines/breadth.py` | `BreadthService(repo, universes, periods, ath)`: `sectors(universe, as_of, periods, near_pct=10, near_basis='52w')` (latest session; stored periods read from / written through to `sector_breadth`, others computed live; each row also `near_high` = {stocks, near}: closes within `near_pct`% of the 52-week or all-time high, always live), `rotation(universe, as_of, period=50, ago={1w}, min_stocks=5, rank_by='ma'|'near_high', near_pct, near_basis)` (sector rank change over `ROTATION_WINDOW`=5 sessions now vs 5 ending `ago` earlier, on `trading_sessions`; MA: stored history when it covers the sessions, else live; near high: live), `update(days=10, since=None)` (from the earliest of 10 days ago, bars (re)ingested since `breadth_watermark`, and `since`), `backfill()`; `HIGH_BASES`, `RANK_BY`; pure `rotation_rows(frame, sessions, lag, window, min_stocks)` |
| `pipelines/repair.py` | `RepairService.run(now)`: re-downloads the dates of open bad-price issues (any stock) and gap issues (`GAP_UNIVERSES` members), `MAX_PER_RUN`=50 a night, each at most once per `RETRY_AFTER` (7 days), `MAX_ATTEMPTS`=3 then gaps accepted as provider holes; bars still bad are removed (archived) with their calc values, `daily_ath` rebuilt for those stocks; returns a summary incl. `earliest_removed`. Rate-limited tries don't count |
| `pipelines/highs.py` | `AthService.refresh(full=False)`: keeps `daily_ath` current per instrument (stocks with daily bars ingested since `derived_state.ath_watermark` recomputed from their earliest such bar; first run / `ATH_VERSION` bump / `full` = everything); runs nightly, before every all-time-high read, and via `markets highs` |
| `pipelines/snapshots.py` | Shared by cross-sectional services: `universe_members(universe, as_of, ...)` (point-in-time watchlist, or `ALL_TRACKED`="all"), `latest_session(snap)`, `clean`, `records(df, columns)` (JSON-safe rows) |
| `pipelines/screener.py` | `ScreenerService`: `fields()`, `run(filter, universe, as_of, include_indices, industry=None, columns=())` (`industry` = one sector; `columns` = extra operands returned, not filtered on) → `{as_of, timeframe, universe, columns, rows}`, `performance(ids, start, end)` (basket vs the benchmark, default `NSE:Nifty 50` = first `benchmarks` member; a non-trading `start` picks on the session before it; ValueError if end < start; used by Scans and the Watchlists Performance view), `saved_scans()`, `save(name, definition)` (upsert by name), `delete(id)` |
| `pipelines/live.py` | `within_hours(now, hours)`, `SESSION_HOURS`, `FEED_HOURS`; `LiveService(feed, instruments, provider, base_ids, clock)` (`add_listener(fn(instrument_id, quote))`: called on the feed thread for every quote): one streaming connection in `FEED_HOURS` (09:00–16:15 IST weekdays; reconnects after `RETRY_SECONDS` 5/10/30/60), latest quote per instrument in memory only (never written to the DB); streams `base_ids` + whatever `watch(ids)` asked for that day (all feed calls on its own thread); `quotes(ids)`, `status()` (connected, session_open, today, last_tick, lost_at), `start`/`stop`, `step()` (one loop pass, for tests) |
| `pipelines/alerts.py` | `AlertService(repo, instruments, live, notifier, clock)`: price alerts in memory, checked on every live quote (`on_quote`, a `LiveService` listener; only today's quotes in `SESSION_HOURS`); a hit is queued and the service's thread marks it triggered (once) then runs `handlers` (first: `_send_message`, Telegram or `off`); `list`, `create`/`update` (ValueError bad input, KeyError unknown, `AlertFiredError` editing a fired one; an already-met alert fires on the current quote), `delete`, `instrument_ids` (streamed all day), `process(timeout)` (one pass, for tests), `start`/`stop` (re-sends messages left unsent by a stop); feed lost ≥ `LOST_NOTICE_AFTER` (30 s) in the session and back again → a message each; pure `is_hit`, `message`, `indian` (Indian digit grouping) |
| `pipelines/movers.py` | Big-movers watchlist: `MoverModel(version)` (XGBoost booster + meta from `models/`; refuses other `features_version`), `MoverService(repo, market, watchlists, instruments, notifier, cutoff, model, universe, clock)`: `score(as_of, rebuild)` (latest Nifty session by default; current `niftytotalmarket` members, all series feed the market features, only `-EQ` stored; skips a scored day; ValueError in the training period / not a session / today before 15:30; warnings: < `MIN_COVERAGE` bars, no VIX bar), `backfill(since, rebuild)` (no messages), `nightly()` (score + `notify` once: sent/off/failed, failed retried next run), `picks(as_of, cutoff)` (list + next session's close-vs-open per stock, live from candles), `days(cutoff)`; `MODEL_VERSION`, `UNIVERSE`, pure `message(picks, warnings)` |
| `pipelines/market_overview.py` | `MarketOverviewService.overview(universe, as_of, limit)` (benchmarks, sectors, breadth, scans, sparklines), `.scan_catalog()`; `ROW_COLUMNS` |

- `backend/scripts/train_movers.py`: trains a big-movers model version (needs the API running; writes `src/markets/models/<version>.json` + `.meta.json`; `--bars` caches the bars, `--predict-out` test-period probabilities).
- `backend/scripts/nightly-update.ps1` (runs `markets update --scheduled`; logs to `logs/update-YYYY-MM-DD.log`, kept 30 days; a failed run also gets a line in `logs/nightly-summary.log`, which is never pruned), `register-nightly-task.ps1` (Windows Task Scheduler).
